# 뭅 · moov.

**MOVE TOGETHER**  
연세대학교 미래캠퍼스 스포츠 매칭 수업용 PWA. React, TypeScript, Vite로 구현했다. 같은 브라우저에서 가상의 학생과 팀 대표로 전환하며 모집, 신청, 승인, 취소를 시연할 수 있다.

## 실행

[공개된 뭅 앱 열기](https://moov-mirae-campus.jj04020985.chatgpt.site)

팀원은 저장소 초대를 수락한 뒤 아래 명령으로 개발 서버를 시작할 수 있다. 개발에 사용한 Node.js 버전은 26.13.0이다. 터미널에 표시되는 주소를 브라우저에서 연다.

```sh
git clone https://github.com/taeu1250-bit/moov.git
cd moov
npm ci
npm run dev
```

수정할 때는 새 브랜치에서 작업하고 `npm test`와 `npm run build`를 실행한 뒤 `main`으로 풀 리퀘스트를 연다. GitHub에 병합한 변경을 공개 앱에 반영하려면 ChatGPT Sites에서 새 버전을 게시해야 한다.

| 목적 | 명령 |
|---|---|
| 편집하며 개발 서버 실행 | `npm run dev` |
| TypeScript 검사 | `npm run check` |
| 참가·정원·권한 규칙 테스트 | `npm test` |
| 정적 앱과 서비스 워커 생성 | `npm run build` |
| 서버가 종료된 뒤 PWA 미리보기 다시 실행 | `npm run preview -- --port 4174 --strictPort` |

PowerShell에서 스크립트 실행이 제한된 경우 `npm` 대신 `npm.cmd`를 사용한다. 오프라인 기능을 확인할 때는 빌드 후 미리보기 명령으로 접속한다.

## 화면과 시연 계정

| 화면 | 직접 해볼 수 있는 동작 |
|---|---|
| 시작·학교 인증 | 시연 계정으로 바로 시작하거나 학교 이메일 형식을 확인하고 가명·입학연도로 프로필 생성. 모의 인증에는 이메일 발송이나 비밀번호 입력이 없다. 이메일 입력값은 저장하지 않는다. |
| 경기 찾기 | 주간 달력의 날짜 이동, 큰 종목 버튼과 전체·용병 모집·친선경기 필터, 제목·팀명·종목·장소 검색, 시간순·최신순 정렬 |
| 경기 상세 | 일시·장소·현장 분담금·모집자·잔여 인원 확인, 개인 또는 대표팀 신청으로 이동 |
| 모집하기 | 종목, 제목, 일시, 네 곳의 운동 장소(대운동장·풋살장·스포츠센터·농구장), 정원, 기존 인원, 분담금, 레벨, 안내를 입력해 등록 |
| 참가 신청 | 용병 모집에는 본인 한 명으로 신청. 친선경기에는 대표자가 자기 팀 이름으로 신청. 매너 수칙 확인 후 승인 대기로 저장 |
| 신청자 관리 | 모집자가 대기 신청을 승인·거절하고 확정 참가를 취소. 확정 및 처리 내역 확인 |
| 내 활동 | 내가 신청한 경기와 모집한 경기 조회. 승인 대기·참가 확정 필터와 상세 화면 이동 |
| 마이페이지·알림 | 가상 계정 전환, 신청·승인 결과 알림, 홈 화면 추가 안내, 시연 데이터 초기화 |

| 가상 사용자 | 역할 |
|---|---|
| 김민서 | 일반 학생. 시작 화면의 바로 시작 계정 |
| 이준 | 축구팀 리베로 대표. 예시 저녁 풋살 및 축구 친선경기 모집자 |
| 한솔 | 축구팀 비즈 fc 대표 |
| 정율 | 농구 동아리 바구니 대표 |

새로 만든 시연 프로필은 일반 학생이다. 모든 계정이 용병 모집에 한 명으로 참가할 수 있다. 친선경기 개설·신청은 대표 계정에서만 가능하고 대상 종목은 축구, 풋살, 농구다.

## 한 기기에서 시연하기

1. **마지막 한 자리** — 김민서로 시작해 ‘저녁 풋살, 한 자리 함께해요’에 신청한다. 인원은 9/10명이고 상태는 승인 대기다. 마이페이지에서 이준으로 전환해 같은 경기의 신청자 관리에서 승인한다. 10/10명과 모집 마감이 표시된다. 김민서로 돌아와 시작 전에 취소하면 9/10명과 모집 중으로 돌아간다.
2. **상대팀 결정** — 한솔과 정율로 차례로 ‘리베로 vs 상대팀 모집 중’에 신청한다. 이준이 한 팀을 승인하면 그 팀은 매칭 확정, 다른 팀은 미선정이 된다. 확정팀이 경기 전 취소하면 상대팀 모집이 다시 열린다. 미선정팀도 다시 신청할 수 있다.
3. **직접 개설** — 모집하기에서 날짜와 장소를 입력해 등록한다. 내 활동 → 내가 모집에서 열 수 있다. 다른 계정의 경기 찾기에서는 등록한 날짜를 선택하면 같은 글이 보인다.
4. **재시연** — 마이페이지 → 시연 데이터 초기화 → 초기화 실행을 누르면 현재 날짜 기준으로 예시 경기를 다시 생성한다. 새로고침은 저장된 정보를 유지한다. 이전 버전의 시연 팀·예시 장소는 새 표기로 읽어 들이며, 사용자가 작성한 모집글과 신청·승인 기록은 보존한다.

참가 정원에는 모집자가 포함된다. 승인 대기 중인 개인은 자리를 차지하지 않는다. 승인 시점에 마지막 자리를 다시 확인하고, 시작 시각 이후에는 승인·취소를 잠근다. 친선경기의 우리 팀 인원은 개설 시 입력한 값이며 상대팀 확정 여부는 별도로 관리한다. 금액 표시는 현장 분담금 안내에 쓰이며 앱에서 결제하지 않는다.

## 원본과 구현의 대응

Stitch ZIP의 `_1`부터 `_7`까지를 순서대로 인증, 경기 찾기, 상세, 모집 작성, 참가 신청, 마이페이지, 신청자 관리 화면에 대응시켰다. 원본의 주간 달력, 카드 순서, 정원 표시, 섹션형 입력 폼과 하단 액션 구조를 사용했다.

- 흰색·블루 계열을 다크 네이비와 형광 라임으로 바꾸고 앱 이름·시작 화면·아이콘에 `moov.`를 적용했다.
- 원본마다 달랐던 하단 메뉴는 경기 찾기, 모집하기, 내 활동, 마이페이지로 통일했다. 내 활동과 알림은 기존 카드와 상태 표시를 재사용한 화면이다.
- 단체 동반 신청 폼은 최종 요청에 맞춰 개인 1명 신청과 대표자의 친선경기 신청으로 교체했다. 실제 비밀번호·연락처·결제 입력은 시연에 포함하지 않았다.
- 프로필에는 가명 아바타를 사용하고 상세 화면은 경기 제목과 일시·장소부터 보여준다. 아이콘과 스타일을 로컬 앱에 포함해 오프라인에서도 표시한다. 원본에 보이는 채팅·찜·신고·문의·작성 중 임시저장은 이번 핵심 시연 범위에 포함하지 않았다.

## PWA 설치와 확인

빌드 시 앱 매니페스트, 192·512px 아이콘과 마스크용 아이콘, Apple 터치 아이콘, 정적 파일을 저장하는 서비스 워커를 준비한다. 첫 온라인 로딩과 캐시 저장을 마치면 연결이 끊겨도 기존 화면을 다시 열고 같은 기기에 신청을 저장할 수 있다.

- **아이폰** — Safari에서 앱 주소를 열고 공유 메뉴의 ‘홈 화면에 추가’를 선택한다.
- **안드로이드** — Chrome에서 앱 주소를 열고 메뉴의 ‘앱 설치’ 또는 ‘홈 화면에 추가’를 선택한다.
- **휴대폰에서 설치 시험** — 휴대폰이 접근할 수 있고 신뢰하는 HTTPS 주소가 필요하다. PC의 루프백 주소는 휴대폰으로 공유할 수 없다. 브라우저별 설치 조건과 방법은 [PWA 설치 안내](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)를 참고한다.

검증한 범위는 TypeScript 검사와 정적 빌드, 도메인 테스트 9건, Windows Chrome에서 실행한 모바일 크기 브라우저 테스트다. 320px·390px 홈의 가로 넘침, 1200px 데스크톱 홈, 모의 인증, 검색, 모집글 개설, 신청·승인·거절·취소, 상대팀 한 곳 확정과 나머지 미선정, 계정 전환, 알림, 새로고침과 초기화를 확인했다. 일반 Chrome 프로필에서 매니페스트·아이콘 응답과 설치 가능성 검사, 네트워크 차단 후 재실행·신청·새로고침도 확인했다. 아이폰·안드로이드 실기기 설치는 별도 확인 항목이다.

## 실제 서비스로 전환할 때

- `src/screens`와 `src/ui`는 화면과 공통 컴포넌트다. 화면은 `src/data/contracts.ts`의 경기 저장소와 세션 인터페이스를 통해 데이터를 사용한다.
- `src/domain`은 참가 정원, 대표 역할, 승인·거절·취소, 한 팀 확정 등의 규칙을 담당한다. `src/data/local.ts`는 변경 전체를 한 번에 저장하고, 같은 브라우저의 탭 변경을 반영한다. `src/data/seed.ts`는 가상의 시연 데이터다.
- 실제 서비스에서는 세션 인터페이스에 검증된 학교 인증을 연결하고, 서버에서 사용자와 팀 대표 권한을 판정해야 한다. 서버 트랜잭션에서 정원과 상대팀 한 곳 확정을 검증한 뒤 온라인 저장소에 반영하고, 변경 사항을 구독과 사용자별 알림으로 전달한다.
- 현재 저장소와 계정 전환은 한 브라우저 안에서 동작한다. 기기 간 공유, 실제 신원 검증, 서버 접근 제어와 푸시 알림은 서비스 전환 단계의 작업이다.
